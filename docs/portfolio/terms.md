# 프로젝트 용어를 쉽게 읽는 방법

기술 이름보다 **어떤 문제를 어떻게 처리했는지**부터 읽으면 된다. 아래 설명은 이 프로젝트에서 사용하는 의미와 예시다.

## 주문과 데이터 저장

| 용어 | 쉬운 뜻과 프로젝트 예시 |
| --- | --- |
| 정합성 | 서로 관련된 데이터가 맞는 상태. 주문이 취소되면 차감한 재고도 함께 되돌린다. |
| 트랜잭션 | 여러 DB 변경을 한 묶음으로 처리. 주문·재고·이벤트 저장을 모두 확정하거나 모두 취소한다. |
| 커밋 / 롤백 | DB 변경 확정 / 변경 취소. 배포 문서의 롤백은 이전 프로그램 버전으로 복구한다는 뜻이다. |
| 낙관적 락 | 조회한 뒤 다른 요청이 먼저 수정했는지 버전으로 검사. 재고 수정이 충돌하면 409로 안내한다. |
| 멱등 처리 | 같은 작업을 다시 처리해도 결과가 중복 반영되지 않게 함. 같은 주문 이벤트가 두 번 와도 통계 행은 하나만 저장한다. |
| 멱등성 키 | 같은 요청의 재시도인지 구분하는 식별 값. 주문 API에 이 키를 적용하는 기능과 현재의 통계 중복 방지는 별개다. |
| 고유키 | 같은 값을 가진 행이 중복 저장되지 않도록 DB가 검사하는 규칙. 주문 통계는 주문 번호로 구분한다. |
| 캐시 / 캐시 무효화 | 자주 읽는 결과를 임시 보관 / 오래된 결과 삭제. 상품 수정 후 이전 상품 캐시를 지운다. |

## 이벤트와 재시도

| 용어 | 쉬운 뜻과 프로젝트 예시 |
| --- | --- |
| 이벤트 | 이미 일어난 일을 알리는 데이터. 주문 생성 이벤트에는 주문 번호와 생성 시각을 담는다. |
| 비동기 처리 | 요청한 일을 끝내기 전에 모든 후속 작업을 기다리지 않는 방식. 주문 저장 후 통계는 나중에 반영될 수 있다. |
| Outbox | 나중에 처리할 일을 DB에 보관하는 테이블. 주문과 이벤트를 함께 저장해 전송 실패 후에도 다시 시도할 수 있게 한다. |
| Relay / Sender | 저장된 일을 가져와 실행하는 작업자 / 유형별 실행 담당 코드. 주문은 Kafka로 보내고 상품 캐시 삭제는 Redis에 적용한다. |
| 선점 | 다른 작업과 겹치지 않게 처리할 일을 먼저 잡는 단계. 이미 잠긴 행은 건너뛰고 담당 토큰과 유효기간을 기록한다. |
| claim token | 작업을 가져올 때마다 새로 만드는 처리 권한 확인 값. 서버마다 고정된 ID가 아니며, 결과 저장 시 유효기간도 검사한다. |
| Producer / Consumer | Kafka에 메시지를 보내는 코드 / 메시지를 받아 처리하는 코드. |
| Topic / Consumer Group | 메시지를 모으는 통로 / 함께 메시지를 나눠 처리하는 수신 그룹. 로그와 통계는 별도 그룹으로 같은 주문 이벤트를 받는다. |
| DLT | 처리를 마치지 못한 메시지를 따로 보관하는 Kafka 토픽. 재시도 후 실패한 메시지나 읽을 수 없는 JSON을 확인할 수 있다. |
| 직렬화 / 역직렬화 | 객체를 전송 가능한 JSON 등으로 변환 / 받은 데이터를 객체로 읽기. |
| 원자적 처리 | 여러 동작을 중간에 다른 작업이 끼어들지 않는 단위로 실행. Redis Lua로 요청 횟수 증가와 만료 설정을 처리한다. 실행 중 오류가 나면 모든 변경을 자동 취소한다는 뜻은 아니다. |

## 로그인과 권한

| 용어 | 쉬운 뜻과 프로젝트 예시 |
| --- | --- |
| 인증 / 인가 | 누구인지 확인 / 어떤 작업을 허용할지 판단. Keycloak 로그인이 성공해도 회원 관리 권한은 우리 DB에서 별도 확인한다. |
| SSO / OIDC | 여러 서비스가 같은 인증기관의 로그인 상태를 이용하는 방식 / 사용자 인증 정보를 전달하는 표준. 이 프로젝트는 Keycloak과 연결한다. |
| issuer / subject | 인증기관 주소 / 그 기관이 발급한 사용자 고유 ID. 이메일만 비교하지 않고 이 둘로 서비스 회원을 찾는다. |
| Realm / Client | Keycloak의 사용자·인증 설정을 나누는 영역 / 로그인 기능을 사용할 애플리케이션 등록 정보. |
| 세션 | 서버에서 관리하는 로그인 상태. Redis에 저장해 여러 백엔드가 공유한다. |
| CSRF | 다른 사이트가 로그인된 브라우저를 악용해 변경 요청을 보내는 공격. 서버가 발급한 토큰을 검사해 방어한다. |
| 같은 출처 / CORS | 프로토콜·호스트·포트가 같은 주소 / 다른 출처에서 API 응답을 읽도록 허용하는 브라우저 관련 정책. AWS 화면과 API는 같은 출처를 사용한다. |
| Secure / HttpOnly | 쿠키를 HTTPS 연결에서만 전송 / JavaScript에서 쿠키를 읽지 못하게 하는 속성. |

## 코드 구조와 배포

| 용어 | 쉬운 뜻과 프로젝트 예시 |
| --- | --- |
| 포트 / 어댑터 | 업무 코드가 호출하는 인터페이스 / 실제 기술로 동작을 수행하는 구현체. 네트워크 포트 번호와 다른 의미다. |
| Command / Result | 서비스에 전달할 입력 객체 / 서비스가 돌려주는 결과 객체. 웹 API 요청·응답 객체와 나눈다. |
| 인스턴스 / Pod | 실행 중인 프로그램 한 개 / Kubernetes가 관리하는 실행 단위. 로컬에서 백엔드 Pod 두 개를 실행했다. |
| 이미지 / 컨테이너 | 프로그램과 실행 환경을 묶은 배포 파일 / 그 이미지로 실행한 프로그램 환경. |
| healthcheck | 실행 상태 점검. 컨테이너가 healthy여도 모든 업무 기능까지 검증됐다는 뜻은 아니다. |
| readiness / liveness | 요청을 받을 준비가 됐는지 / 재시작이 필요한 실행 상태인지 확인하는 검사. |
| 롤링 업데이트 | 실행 단위를 순차 교체해 새 버전을 적용. 로컬 Kubernetes에서 실습했다. AWS의 단일 컨테이너 교체와 구분한다. |
| Reverse Proxy | 요청을 받아 목적지 서버로 전달. Caddy가 화면·API·SSO 주소를 구분해 전달한다. |
| CI/CD | 코드 검증과 배포 과정을 자동 실행하는 흐름. 여기서는 Jenkins의 ‘지금 빌드’를 누르면 테스트부터 AWS 배포까지 실행한다. |

실제 구현과 검증 범위는 [핵심 구현 사례](case-studies.md), 실행 명령은 [로컬 개발 안내](../local-development.md)를 참고한다.
